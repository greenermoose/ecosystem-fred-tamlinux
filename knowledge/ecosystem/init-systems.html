Init & Service Supervision: The Case for runit

← Back to Ecosystem Index

Process ID 1 (PID 1) initializes hardware and supervises background services. Tamlinux evaluates runit and systemd against the principles of minimalism, determinism, and the Unix philosophy.

1. Why Tamlinux Chose runit (1.2+)

For its target Void Linux and antiX base, Tamlinux selected runit (Decisions D68, D126):

  • Unix Simplicity: ~5,000 lines of pure C versus systemd's ~1.5 million lines. A service is just a directory containing a short executable script named ./run.
  • Deterministic Parent Supervision: runsv is the direct process parent of each supervised daemon. If a daemon crashes, runsv detects the termination signal immediately and restarts it deterministically.
  • Sub-Megabyte Footprint: runit consumes less than 1 MB of RAM across the entire system, preserving crucial memory on vintage or low-spec hardware.
  • Instantaneous Boot: Starts services immediately without heavy XML/JSON parsing, complex dependency graphs, or binary socket handoffs.

2. Why Tamlinux Is Moving Away from systemd

While systemd manages the current Arch 0.x workstation, it is scheduled for removal on the independent base (Milestone 1.2):

  • Monolithic Scope Creep: systemd has grown to absorb DNS resolution, network management, time synchronization, user home encryption, and log indexing into invasive background daemons.
  • Resource Waste ("Value per Watt"): Multiple background worker threads, periodic timers, and binary journal flushers wake up the CPU constantly, preventing low-power hardware sleep states.
  • Invasive Architectural Lock-in: Upstream software increasingly assumes systemd-specific D-Bus APIs, breaking modularity. Tamlinux actively decouples its shell services from all systemd assumptions (D136).

3. Seat Management without systemd: seatd

Historically, running Wayland compositors rootless required systemd-logind to mediate GPU and input device access. Today, this is solved cleanly by seatd and libseat:

  • A tiny standalone C daemon (~50 KB RSS) that grants unprivileged Wayland compositors access to DRM devices.
  • Enables Sway to run smoothly on Void and antiX with zero systemd or elogind dependencies.
