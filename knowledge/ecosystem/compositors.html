Windowing & Compositors: Why Sway

← Back to Ecosystem Index

In a Wayland environment, the compositor is the display server, window manager, and hardware modesetting coordinator. Tamlinux is standardizing on Sway, built on the wlroots library, replacing interim Hyprland for version 1.0.

1. Why Wayland Over X11

The 40-year-old X Window System (X11) has been completely retired from Tamlinux:

  • Security Isolation: Under X11, any connected client can spy on keystrokes and window buffers. Wayland enforces strict client isolation.
  • Tear-Free Direct Rendering: Wayland clients render directly into GPU or shared memory buffers, which the compositor scans out to DRM/KMS. Every frame is synchronized without latency or tearing.
  • Independent Multi-Monitor DPI: Wayland supports mixed-resolution, fractional display scaling (e.g. 1.25×) per monitor.

2. Why Sway Was Selected (0.7–1.0+)

On 2026-10-03, Fred chose Sway as Tamlinux's permanent compositor (Decisions D64, D124):

  • Clean C Codebase: Written in disciplined C99. Free from heavy C++ template bloat, complex compiler dependencies, and rapid breaking ABI churn.
  • Software CPU Rendering (WLR_RENDERER=pixman): Sway can run using pure CPU rendering via pixman. This enables Tamlinux to boot and display a responsive graphical desktop on vintage circa-2006 hardware where GPU drivers lack OpenGL 3 support.
  • systemd-Free Rootless Execution (seatd): Sway works natively with seatd / libseat, requiring zero systemd or elogind daemons.
  • Stable i3 IPC: Sway's rock-solid JSON IPC allows Tamlinux plugins (like fred.workspaces and fred.monitor) to manage outputs, focus, and layout reliably.

3. Why Hyprland Is Retiring at 1.0

Hyprland provided the early environment for Tamlinux 0.x, but is being phased out:

  • Hardware Requirements: Written in C++23; strictly requires modern GPU acceleration and cannot run with software CPU rendering on vintage hardware.
  • Rapid Breaking Changes: Frequent internal refactoring causes plugin ABI mismatches across minor updates.
  • Upstream Friction: Hyprwm's policy bans AI-assisted pull requests outright; because Tamlinux uses AI pair programming, carrying fixes upstream created friction.
  • Carried Local Patches: Tamlinux had to maintain multiple local patches (DPMS inheritance on connect, idle timer no-ops) to keep multi-monitor setups stable.

4. Other Evaluated Compositors

  • Niri: Intuitive horizontal scrollable ribbon layout in Rust; however, it strictly requires hardware OpenGL/Vulkan and cannot run on software pixman renderers.
  • river: Dynamic tiling in Zig with separate external layout generators. Elegant, but less mature IPC ecosystem.
  • labwc: Stacking compositor on wlroots with Openbox configuration; kept in view as a lightweight floating desktop option.
  • Wayfire: 3D Compiz-style effects; creates unnecessary GPU energy consumption.
