Why Tamlinux Carries Patches

← Back to Ecosystem Index

A key responsibility of the ecosystem-fred-tamlinux repository is maintaining the public record of every third-party package Tamlinux runs patched.

1. Why Not Upstream Pull Requests?

Open-source projects are increasingly closing or restricting their public pull-request queues. Writing code has become cheap, but reviewing it remains expensive. Upstream maintainers are overwhelmed by machine-generated PRs.

Projects from Ghostty and Zig to Hyprland have restricted outside contributions or strictly banned AI-assisted pull requests outright. The patches Tamlinux creates are developed by AI coding agents directed by Fred, with tool and prompt recorded in AI_PROVENANCE.md.

Rather than flooding upstream queues with contributions maintainers do not want to review, Tamlinux publishes fixes in a way that costs upstream nothing: a clean branch on a public Git fork that anyone can inspect, compare, and merge if they wish.

2. How a Patch Is Carried Safely

greenermoose/<Upstream>   (public fork off release tag)
        ↓  tam-ecosystem export (git format-patch)
~/pkgs/<pkg>/             (PKGBUILD with pkgrel <arch>.N)
        ↓  tam-ecosystem install
packages/<pkg>/           (recipe, patches, and pacman hook)
  • Tarball + Patches: Packages are built from official upstream source tarballs with applied patches. Compiler flags, commit hashes, and plugin ABIs remain stable.
  • Loud Pinning: Rebuilt packages carry a pkgrel <arch>.N suffix and are served from [local-patches], listed first in pacman.conf. Silent pinning tricks like IgnorePkg are never used.
  • Automatic Retirement Hooks: A pacman transaction hook (50-*.hook) compares versions on every system update. When upstream ships a release containing the fix, the hook warns loudly, and the patch is retired cleanly via tam-ecosystem retire.
