Desktop Application Suites: KDE vs. GNOME

← Back to Ecosystem Index

A functional workstation environment requires a dependable set of graphical daily-driver applications: file management, document viewing, text editing, image manipulation, media playback, and utility tools. Tamlinux evaluates software suites from both KDE (KDE Gear, Plasma utilities, KDE Frameworks 6) and GNOME (GNOME Core, GNOME Circle, Libadwaita) to determine compatibility with the Tamlinux botanical architecture.

1. Botanical Architecture Requirements

Tamlinux couples a distinct base operating system with an independent desktop layer:

  • The Root-stock (Minimal Void Linux): Supervised deterministically by runit, using seatd for seat arbitration, and packaged with XBPS. Applications must execute reliably without requiring systemd PID 1, systemd --user session units, or elogind.
  • The Cultivar (Sway + Quickshell): A keyboard-driven tiling compositor (Sway on wlroots) paired with a declarative Qt Quick / QML shell (Quickshell) themed with the Tamarack palette. Applications must respect Wayland tiling geometries, support Server-Side Decorations or frameless layouts, and adhere to our Value per Watt tenet (no perpetual background polling or runaway indexing loops).

2. Key Findings: KDE Frameworks 6 vs. GNOME Libadwaita

  • Toolkit Alignment: Tamlinux's desktop shell is built on Qt Quick and QML. KDE applications share Qt 6 runtimes, font rendering caches, and memory pages. In contrast, GNOME's GTK 4 / Libadwaita stack introduces a secondary graphics toolkit and memory footprint.
  • Window Decorations & Screen Real Estate: KDE applications support standard Wayland Server-Side Decorations (SSD via xdg-decoration-unstable-v1), surrendering window frames cleanly to Sway. GNOME's Libadwaita enforces thick Client-Side Decoration (CSD) headerbars that consume 40–50 pixels of vertical screen space and duplicate tiling keybindings.
  • System Supervision Independence: KDE Frameworks 6 (Tiers 1–3) is engineered around POSIX/libc standards and is completely decoupled from systemd. Core KDE applications run cleanly on Void Linux with runit. GNOME applications increasingly expect logind D-Bus interfaces and systemd user session management.
  • The Indexing & Daemon Tax: Both environments provide background indexing engines (Baloo in KDE, Tracker/TinySPARQL in GNOME) and heavy relational PIM database daemons (Akonadi in KDE, Evolution-Data-Server in GNOME). On vintage circa-2006 hardware, both engines thrash RAM and disk I/O. However, Baloo is trivially disabled via declarative config (baloofilerc), whereas GNOME Core apps depend deeply on Tracker/GIO services.

3. Recommended Application Selections

  • Okular (Selected - Document Viewer): Best-in-class multi-format document viewer (PDF, ePub, PostScript, Markdown, DjVu). Fast, lean (~30 MB RAM), rich annotations, zero background daemons.
  • Kate (Selected - Text & Code Editor): Exceptional graphical editor with native LSP client, Git integration, multi-cursor editing, and split views in a lightweight ~35 MB footprint.
  • Dolphin (Selected with Baloo disabled - File Manager): Industry benchmark dual-pane file manager with embedded terminal support. Configured with Indexing-Enabled=false for maximum efficiency.
  • KCalc (Selected - Calculator): Scientific/hexadecimal calculator powered by GMP/MPFR with zero daemons and instant startup.
  • Filelight (Selected - Disk Space Visualizer): Interactive radial visualizer built natively with Qt Quick and QML.
  • Ark (Selected - Archiver): Clean, reliable Qt6 frontend for libarchive and compression tools.
  • KDE Connect (Selected - Device Bridge): Peerless mobile integration daemon and client; runs standalone on Sway.

4. Tamlinux Cultivar Native Tools

For system settings, desktop menus, and calendar management, both upstream suites are disqualified (GNOME Control Center is bound to GNOME Shell; KDE System Settings is bound to KWin; both PIM engines are excessively heavy). Tamlinux provides native Quickshell components:

  • Tamlinux Settings: Declarative, keyboard-navigable control panel built on Quickshell and libtam.
  • fred.monitor: Native multi-display layout, resolution, and retraining manager.
  • fred.clock: Lean, file-backed calendar and clock without database daemons.
  • fred.sysinfo: Transparent hardware and resource telemetry.
