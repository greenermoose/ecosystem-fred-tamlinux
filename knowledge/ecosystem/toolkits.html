Desktop Shell: Quickshell & Tamlinux Shell

← Back to Ecosystem Index

The desktop shell provides the visible interface: status bars, menus, workspace switchers, notifications, and panel popups. Tamlinux separates window management (Sway) from desktop presentation, running an independent shell powered by Quickshell and Qt Quick.

1. Why Quickshell Was Selected

Quickshell (created by outfoxxed) is a desktop shell development toolkit built atop Qt Quick and QML:

  • Reactive Declarative UI: QML binds properties directly to system state. When battery levels shift or network connections drop, UI elements react automatically without manual polling.
  • Direct Wayland Layer Shell Integration: Talks natively to wlr-layer-shell. Panels anchor cleanly to screen edges, reserve desktop struts, and handle keyboard focus seamlessly.
  • Multi-Monitor Resilience: Automatically duplicates bars and synchronizes layouts across connected screens without restarting the session.
  • Lightweight Memory Profile (D126):** A full multi-display Quickshell session consumes only ~60–80 MB of RAM, far less than Electron or GNOME Shell.

2. Decoupling from Omarchy (Step 0.4.3 & D136)

The Tamlinux Shell originally inherited visual conventions from Omarchy 4.0.4. However, Tamlinux executed a complete, clean fork and decoupling (Decisions D102, D103, D124, D136):

  • No Monolithic Omarchy Dependencies: All hardcoded /usr/share/omarchy paths, invasive update hooks, and external servers were purged. Step 0.4.3 proves that Tamlinux installs on a fresh machine with zero Omarchy code.
  • Compositor Protocol Neutrality (D125): Rewrote the shell's state engine into ProtocolState.qml, which talks standard Wayland protocols (ext-workspace-v1) and Sway rather than private Hyprland IPC.
  • Unified Hover Architecture (D128): Standardized all plugin hover tooltips and panel footers onto a shared, dimmed caption component (Tam.Ui.VersionFooter).
  • GPL-3.0-or-later Ownership: All ported components are maintained publicly in the tamlinux repository under copyleft terms.

3. Evaluated Alternatives

  • Waybar: Excellent, lightweight C++ status bar, but limited to static bar formats; cannot render interactive rich panels, calendars, or sliders.
  • Astal & AGS (GTK Shell): Uses TypeScript and GJS; higher memory footprint and JavaScript garbage collection pauses compared to compiled QML.
  • EWW (ElKowars wacky widgets): Standalone Rust widget engine; custom Yuck S-expression language becomes unmaintainable for complex multi-screen panels.
